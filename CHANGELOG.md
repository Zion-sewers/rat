## [Unreleased]

### Added
- Deterministic intake normalization: schema-gated entry with explicit truncation policy and structured fallback (rat #76, ch.3 "Controlling Text-Only LLM Behavior at Inference Time" — ADAPTATION: schema validation + deterministic normalization are established API-design practice; the policy shape, error-code set, and budgets are this unit's calibration, pinned by the in-module calibration sets): `normalize_input` in `src/mcp_guard/intake.py` runs inside `Gateway.call_tool` first among the request checks (the `caller_trust` type check precedes it), before the identity check, the trust check, and the rule of two, and returns either a canonical `NormalizedIntake` (sorted keys, over-long strings truncated head + `[TRUNCATED]` + tail) or an `IntakeFailure` with a stable error code (`INTAKE_INVALID_TOOL`, `INTAKE_INVALID_ARGUMENTS`, `INTAKE_NON_JSON_VALUE`, `INTAKE_TOO_LARGE`, `INTAKE_MISSING_METADATA`, `INTAKE_MISSING_IDENTITY`); on failure the gateway returns the structured fallback (`{"mcp_guard_intake": {"status": "fallback", "error_code": ..., "policy_tag": ...}}`) and the transport is never called, so zero malformed inputs reach the model or the server. Checks in fixed order: tool name (non-empty string after strip, bounded, no NUL/control chars, no lone surrogate — a lone surrogate cannot be encoded to bytes and fails as `INTAKE_NON_JSON_VALUE`), arguments shape (mapping, non-empty string keys, `max_depth` 32 so hostile nesting fails as a schema error), JSON-serializability (`allow_nan=False`, so NaN/Infinity fail; bytes/set/custom objects fail; lone surrogates in any string value or key fail, and the canonical form is UTF-8-encoded as a belt-and-braces check), total size (`max_arguments_chars` 65536 on the canonical JSON), operator-declared `required_metadata` (e.g. `"locale"`, each a non-empty string — the issue's locale example, mapped to declared metadata since no locale substrate exists in the repo), and `require_identity` (the identity-bound requirement: a gateway with no identity bound fails when it is set; there is no "tier" concept in #70's identity model, so this gates on presence of a bound identity only). Budgets are in characters (head/tail per string value, total cap on the canonical JSON; head 1536 + tail 512 by default) — the repo has no serving tokenizer, so the numbers are this unit's calibration, never claimed as tokenizer measurements. An `INTAKE` audit event is recorded on every call that reaches intake (outcome ok/fail + policy tag + error code + truncation flags — never values, never metadata values). Shipped defaults are permissive: the schema gate is on, but no required metadata and identity not required until the operator declares them in the policy file. Live consumers: the gateway (the CLI `gateway` subcommand passes a request's `"metadata"` object through and marks a fallback line with `"fallback": true` plus the top-level `error_code`, so a consumer need not parse the result body to tell a fallback from a result) and `mcp-guard intake --file request.json [--policy policy.json] [--identity-bound]` (one JSON object, exit 0 ok / 1 fallback / 2 input error; `--identity-bound` pretends an identity is bound, so a policy with `require_identity` can return ok offline; the ok-path prints the normalized request, content included — do not pipe stdout into logs). 55 tests in `tests/test_intake.py`, including the 20-case calibration set covering all six error codes and gateway integration proving zero transport calls on malformed input. 21 new defaults-registry entries.
- Concealment-technique catalog for monitor evasion (rat #75, Ward/Apollo 'CTRL-ALT-DECEIT' arXiv 2511.09904, MLE-Sabotage — ADAPTATION: the paper contributes the three technique definitions only, partial extract sections 1-3; detector designs, pattern lists, and thresholds are this unit's calibration, not paper numbers): `src/mcp_guard/concealment.py` holds the catalog as data (`CatalogEntry` per technique — pattern, named detector, false-positive calibration set, regression case; new techniques are added as entries, never as prose) and three deterministic pre-model detectors on tool-call artifacts, no LLM judge in the hot path. Redundant-code wrapping (`redundant_code_scan`): dead/no-op ratio around privileged tool calls (line patterns for `pass`-only / `except: pass` / constant-false branches (branch tests fold by a small safe constant evaluator, so `if 1 == 0:` counts exactly like `if False:`), an `ast` pass for unreachable statements after `return`/`raise`/`break`/`continue` and dead arms of constant-folded `if`/`while` tests, duplicated identical blocks >= 3 lines (only on code-shaped input — a diff, or text that parses — and only windows with at least two distinct lines, so repeated log prose does not trip); a `SyntaxError` falls back to line patterns, never raises), tripping iff the ratio reaches 0.35 AND the artifact names a privileged tool AND holds >= 20 code lines — a stub-heavy file with no privileged call never trips; diffs are measured on added lines only (a diff is recognized by a `diff --git` or `@@` header only), and a JSON envelope is unwrapped to its string leaves first (tool results arrive as JSON, and the flat dump is one line). Augmentation-embedded payloads (`augmentation_scan`): staged files against an operator-supplied `PipelineManifest` (ordered stages with `reads`/`writes`, `declared_inputs`; relative paths only, a trailing `/` declares a directory) — `unreferenced` (in no stage's reads/writes and not a declared input) and `downstream_only` (read by exact file name by a stage, written by none, not a declared input, no directory read covering it — a directory read vouches for its contents); directory matching is exact-prefix with the `/` boundary (`data/train/` never covers `data/train_evil/`). Side-tasks (`side_task_scan`): tool calls outside the bound delegation contract's allowlist — the contract's tools are the declared task graph's node set (a named approximation; the repo has no task-graph type), names normalized before the check, and with no contract bound the check is unavailable, never a finding. Live consumers: `Gateway.call_tool` runs the redundant-code detector on the canonical JSON result text before tokenization (privileged set = explicitly HIGH-listed tools plus the tool just called when it is HIGH) and the side-task check per call before send when a contract is bound (`gateway --contract`, passed through the lifecycle); findings record a `concealment_scan` audit event (technique, rule id, ratio, off-graph names — never content) only when a check trips; policy `"concealment": {"mode": "audit"|"enforce", ...}` defaults to audit-only, and `enforce` mode raises `ConcealmentBlockedError` on a tripped result and `SideTaskDeniedError` before send on an off-graph call; the CLI gateway loop catches both as per-request denials (the standard denied line with the audit delta), so an enforce-mode trip denies one call instead of ending the session, and a blank tool name is an error line, never a dead session. `ConcealmentVerifier` takes an optional policy: a disabled augmentation-embedding defers straight to the senior. `ConcealmentVerifier` (in `delegation.py`) is the augmentation detector as a `SeniorVerifier` pre-gate over a delegation's staged files: it REQUIRES an inner senior verifier, runs first, and a concealment REJECTED blocks landing even when the senior would approve; `delegate --pipeline-manifest <file>` (and `--resolve-pending`) chains it in front of `--verify-command`, and a manifest without `--verify-command` is refused. `mcp-guard concealment --staged-dir <dir> --manifest <file> [--privileged-tools a,b]` is the direct audit surface (one JSON object, exit 0 clean / 1 findings / 2 input error (a missing directory, an unreadable file, or a malformed manifest); hidden files are audited (only hidden/tooling directories are skipped, listed as `skipped_dirs`), the report states `redundant_code_files_checked` and `side_task_checked: false`, and the staged directory is the staged deliverable set, not a source tree; an example manifest ships at `docs/examples/pipeline-manifest.json` and the README lists the feature). Calibration sets in-module per technique (11 cases; the tests assert every case's expected verdict) and disabled-detector regression proof per technique (the same malicious input trips with its detector enabled and passes with it off). 68 tests in `tests/test_concealment.py`, including gateway audit/enforce integration, delegation end-to-end (a junior staging an unreferenced file never lands it, senior unconsulted), CLI exit codes, and the round-1 fix-forward regressions (constant-expression branches, dotfile payloads, log prose, enforce-mode session survival, verifier policy, normalizer pin). 25 new defaults-registry entries.
- PII mask-then-unmask pipeline for external model calls (rat #74, Huyen ch.10 input guardrails): `MaskPipeline` (one instance = one session, own `PiiTokenizer` namespace, separate from the gateway's tool-call tokens) masks an outbound prompt and unmasks the model's complete response; per-class mask-vs-block `MaskPolicy` (default mask, `{"default": "mask", "per_kind": {"api_key": "block"}}`, unknown kinds/actions/keys fail closed, `approver` rejected as a dead rule); block raises typed `MaskBlockedError` before any masked text leaves, and tokenize-then-revoke runs in a single pass so a blocked value leaves no token a later response could recover; session-scoped rotated placeholders (a fresh random 64-bit session tag baked into the token string, so two sessions — in one process or across processes — mint the same string for different values only on a tag collision, negligible at 64 bits, and a gateway token can never resolve against a pipeline map; closed pipeline raises `MaskSessionClosedError` instead of silently returning masked text); streaming via `StreamingResponse` (chunks forwarded still masked, `finish` unmasks exactly once at completion, no per-chunk unmask entry point, `buffered_text` for the still-masked partial if finish raises); reverse dictionary in-memory only with audit events carrying kinds/counts only. Only tokens this pipeline minted in this session resolve; unminted token-shaped text passes through untouched. `PiiTokenizer` gains a `token_prefix` namespace and `revoke` (revokes only tokens minted fresh by the call being blocked, never a token an earlier prompt already disclosed; withdrawn numbers are never re-minted). 40 adversarial tests in `tests/test_mask_pipeline.py`, including a fake model client driving the full mask -> call -> unmask loop and the aliasing case (session B mints a different value first, then receives session A's stale placeholder). No model client ships in rat: the harness owns the call; the spec carries the worked sequence
- Compositional risk scoring (rat #73, Koenigstein ch.12 deterministic-first pattern): per-category caps on the trust-context scanner (injection 0.70, exfiltration 0.60, format 0.25, invisible-chars 0.50 — contribution is `min((raw + bonus) * mult, cap)`, so one loud signal class can never dominate the verdict at any tier; a single saturated category reaches at most its cap — HITL, never BLOCK — by itself, at the shipped thresholds), stacking bonus for dense multi-signal prompts (>=3 exfiltration cues +0.30, >=4 injection cues +0.20, folded into the category before the cap, so it can lift a sub-cap category toward its cap but never break it; the bonus is routing-real at the shipped weights at the developer tier — conversation-harvest 0.8 + markdown-image-exfil 0.45 + secret-disclosure-request 0.30 sum 1.55 raw, scoring 0.3875 ALLOW without the bonus and 0.4625 HITL with it, so the bonus alone flips that routing — and the shipped exfiltration weights were retuned to make it so: markdown-image-exfil 0.9 -> 0.45, secret-disclosure-request 0.5 -> 0.30; a single weak cue no longer HITLs at the untrusted tier by itself (the secret-disclosure cue, 0.30 ALLOW — markdown-image-exfil at 0.45 still HITLs alone), two new format rules (hidden HTML comment, long base64 blob — hex-only runs such as SHA-256 digests do not match, while a realistic JWT does match as a known false positive bounded by the 0.25 cap; a format signal can flip a HITL to BLOCK in combination, 0.25 + 0.70 = 0.95), invisible characters as a scored category (0.025 per Cf/Cc finding, capped at 0.50 — two stray zero-width characters still allow at 0.05, dense obfuscation at 16+ reaches HITL), and gated semantic review: an injectable `SemanticScorer` runs only when the lexical score lands in the uncertainty band [0.20, 0.80], and in the band its verdict REPLACES the lexical score (the judge decides uncertain cases, so it can clear a false positive as well as escalate), used unweighted and capped at the largest category cap (0.70) — the judge can never BLOCK, by design; the tier decides whether the judge runs, never what the verdict is worth — with a bounded 512-entry LRU cache keyed by content hash (RAW scorer scores, per scanner instance with the scorer fixed at construction) and fail-soft fallback to the deterministic score; scores are quantized to 4 decimals before routing, so threshold comparisons are decimal-exact; the audit shape carries capped `category_scores`, `stacking_bonus` (+ per-category bonus and per-category clipped amounts), raw `injection_score` / `exfiltration_score`, `semantic_score` / `semantic_review` / `semantic_cache_hit` / `semantic_calls`, and the gateway `inbound_scan` audit event records the semantic review including calls and cache hits (the cache-hit rate is the fraction of in-band scans — reviews "in-band", "cached", and "failed" — with review "cached"; a failed call counts as a non-hit). A live scorer ships with this unit: `OllamaSemanticScorer` (stdlib-only `http.client` transport, local `qwen2.5:7b` on `http://localhost:11434` by default, 10s timeout, strict `{"risk": ...}` validation; every transport failure including a garbage status line raises `SemanticScorerError`) — OFF by default, wired either via `Gateway(semantic_scorer=...)` or the policy file's `inbound_scan.semantic_scorer`; with none configured the deterministic score stands (deterministic-only by default, yes; same verdicts, no, deliberately — caps retire single-category BLOCK, two format rules are added, and invisible characters now score). A gateway given both a scanner and a semantic scorer refuses to construct rather than silently dropping the scorer. `tools/scan_weight_tuning.py` is the weight-tuning harness: one-weight / one-cap / one-bonus / threshold adjustment -> re-run over the labeled fixture corpus -> bypass-rate delta reported (baseline 0/16 bypass, 0/7 overblock on the labeled fixture corpus) and any routing mismatch against a label fails the run — in the baseline or the tuned run — so HITL-versus-BLOCK drift cannot pass silently. Numbers are the issue's (book-mined, secondary-only evidence, unmeasured on live traffic), not measurements. Caps change eight #72 pins by design, all from BLOCK to HITL (single-category auto-block is retired — in enforce mode a HITL still escalates for a second approval): tool injection 0.70, travel-agent exfiltration 0.60, markdown-image exfiltration 0.60, untrusted double-exfiltration 0.60, NFKC fullwidth injection 0.70, long hostile input 0.70, tool-tier-beats-untrusted (tool now HITL, not BLOCK), and the to_dict acceptance shape (1.0 BLOCK to 0.725 HITL); developer double-exfiltration stays HITL at 0.45 (1.8 x 0.25, the #72 pin restored by the cap-after-multiplier order)
- Identity propagation (rat #70): the agent acts with the user's permissions, never a super-key — `PermissionScope` (one user, servers, tools, optional expiry; deny-by-default; unknown scope keys rejected), `CredentialHandle` + `IdentityVault` (per-user handles that are references, never keys; no shared/global credential API exists; revocation enforced live per call for a vault-bound context; vault file mode 0600 enforced on every save on POSIX (best-effort on Windows, which has no POSIX permission bits)), `IdentityContext` (bound scope + handle + REQUIRED vault — a context whose vault never issued its handle is refused at bind time; one-way `user-<hash>` correlation token — a truncated unsalted hash, reversible with the user list, never a secret; raw user id never in any log). Enforced in the gateway (identity check before the trust check; audit events `identity_denied` / `identity_expired` / `credential_refused`; tool list filtered to the scope; the gateway re-validates the handle at bind) and the lifecycle (`begin_task` refuses out-of-scope servers before spawning anything; teardown and task-end audit events carry the identity token); live consumers are `mcp-guard gateway --identity scope.json` and `mcp-guard delegate --identity scope.json` (admission control: the contract's tools must be inside the delegating user's scope, refused before the junior starts). Authentication itself (OAuth / JWT / mTLS) stays a deployment concern; the library enforces the issued scope, it does not authenticate the user — a locally authored scope file is self-asserted, not authenticated. Identity is opt-in at the CLI: without `--identity` the gateway keeps its legacy declared-trust behavior and delegation's ceiling is the contract alone; making identity mandatory is a breaking change that needs a re-scope decision. The CLI's vault is ephemeral and in-process, so there is no cross-process revocation source in the shipped CLI session
- Memory poisoning defenses (rat #71, MPBench threat model): untrusted input must never become trusted memory — `_MemoryWriteGate` (sensitive-pattern gate on every write: SSN, Luhn-gated payment cards (13–19 digit runs, grouped or contiguous), PEM private-key blocks, `AKIA...` / `sk-...` shapes (gateway shapes plus the gate's own word-boundaried `sk-` shape at 10+ characters); refusals name only the pattern kind, never the value; email/phone not refused), `MemoryNamespace` (auth-bound (org, user, kind) namespaces — semantic / episodic / procedural / profile — the user half is a vault-issued `IdentityContext`, never a client-side string; the key carries the one-way audit token, never the raw user id; a caller cannot address another user's namespace through any `MemoryService` API), `MemoryService` (the single choke point and the ONLY public write path: constructed with the deployment's trusted vault — contexts from any other vault are refused — live identity re-validation, TRUSTED writes require the deployment-issued `memory.write_trusted` capability in the caller's scope, gate receipt bound to namespace key + content hash + provenance and HMAC-tagged with a per-gate secret the gate alone holds, receipt-checked store that refuses hand-built and cross-gate receipts; the gate, store, and receipt are module-private and the service constructs its own — no public bypass, the mutation test reaches the store's private `_write_raw` through the service's private store only). Trust is provenance, not content: `recall_trusted` returns only TRUSTED-provenance entries, so untrusted tool output never returns as trusted context; `write_tool_output` forces UNTRUSTED for tool results and a TRUSTED claim with a tool source is refused, so the quarantine does not depend on the caller labeling the poison correctly (remaining boundary, stated plainly: `source` is caller-declared, so a caller that HOLDS the trusted-write capability and lies about origin defeats the check — the capability is the authentication, and the deployment must issue it only to operator identities). `MPBENCH_SCENARIOS` (5 executable scenarios: 2 instruction poisons quarantined, 3 secret poisons refused) plus mutation tests proving each defense load-bearing (gate for secrets, service path + provenance label for instruction poison); audit log records write decisions, never content. Store is in-memory only; entries serialize through the `MemoryEntry` mapping contract, which preserves the provenance label across restarts. Authentication stays a deployment concern
- Central MCP gateway (`mcp-guard gateway`, rat #66): trust-level enforcement in the request path (a low-trust caller can never trigger a high-trust read), pre-model PII tokenization with detokenization on later calls, and an audit log of events, never content (the one exception, added by rat #69: the approver name on an `escalation_approved` event, which records as a per-session `[APPROVER_n]` token, never verbatim and never resolvable back to the value)
- MCP least-privilege lifecycle (rat #68): servers off by default, narrow per-task enablement via `ServerRegistry`, and post-task teardown verified against the live process (`TeardownReport`; a surviving server fails the teardown instead of reporting clean). The `gateway` subcommand is the production consumer: the session is one task, and `--servers` enables multi-server tasks via stdin control lines
- Rule-of-two escalation + PII pseudonymization before any output (rat #69): on gateway calls, a HIGH-trust mutating tool on untrusted input escalates and is denied before any send without a second approval (`SecondApproval`, audited; the approver name records as a per-session `[APPROVER_n]` token, the whole field pseudonymized, never verbatim and never resolvable back to the value) — but the same caller can attach its own approval or declare its input trusted, so the control stops accidental omission and creates an audit trail, it does not enforce two distinct humans; the harness must obtain approval from a distinct principal out of band; the fuzzer is exempt from the rule (it does not run through the gateway). Fuzz reports (table/JSON/SARIF) are scrubbed at the emit boundary, before any preview truncation, emit-only and unconditional (no opt-out), so no raw structured PII of the detected classes reaches any report (names and bare 9-digit national IDs excepted); the detector also matches +972 Israeli mobiles and uses a bounded email pattern plus a per-family pre-filter (1M-char runs covered by regression tests with a 10s bound). Gateway CLI lines print the tokenized tool name, never the raw name — including the annotated tool list, scrubbed at its print site — and rejected trust values are never echoed back

## [0.1.0] - 2026-06-03

### Added
- Initial release of mcp-guard
- Stdio transport with JSON-RPC 2.0 handshake
- Schema-aware adversarial payload generation (5 probe types)
- Dynamic fuzzing engine with SAFE / FINDING / CRASH classification
- Static schema scanner with shell injection, SSRF, and missing-schema rules
- CLI with `fuzz` and `scan` subcommands
- Output formats: table, JSON, SARIF
- Zero runtime dependencies (Python 3.11+ stdlib only)
